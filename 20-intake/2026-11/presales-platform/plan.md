## 0.5 定位重述（2026-11-02，PM 确认）

### 一句话

售前把客户信息丢进来，助手像面试官一样追问补齐；然后把每条需求标成「现在能做 / 换个方式能做 / 规划中（不能签）/ 做不到」。做不到的打包成一段可复制的话发给产品；其余的生成一页 HTML 场景说明发给客户确认。

### 与已建引擎的差异（证据：handoff PS-1～PS-23，未在本机运行验证）

| PM 要的 | 现在有的 | 处理 | 级别 |
|---|---|---|---|
| 追问式对话，问到需求清楚为止 | 一次性填五问 → L0～L5 流水线出 6 块包 | **新做**（核心改动） | 引述 |
| 逐条需求判定能否满足、怎么满足 | 【现有/原型/规划】分层 + 合同可写卫兵，但只在块 4 | **复用**，改成每条需求一行的判定表 | 引述 |
| 做不到的单独列出，一键复制发产品 | 块 6「待确认」是问客户的，不是发产品的 | **改** | 引述 |
| 需求定稿后出 HTML 用户故事/场景，给客户回报 | 只有 Markdown 导出，6 块包是内部格式 | **新做** | 引述 |
| 知识底座（手册 + 分层表） | 12 篇手册；竞赛（PS-23）、光谱（PS-24 草稿）分层表 | **复用**，按试点被问频次补 | 引述 |

### PRD 骨架（11-15 复审 accept 后展开到 `30-prd/presales-toolkit/`）

1. **用户与时机**：一线售前；会前（初次了解客户）、会后（客户反馈后再补）各用一次。
2. **对话流程**：输入客户基本信息 → 助手按缺口追问（一次一问，带推荐答案）→ 每轮更新需求清单 → 售前确认「需求已清楚」后进入判定。
   - 待定：追问的缺口清单（行业、规模、现有系统、想解决的问题、预算/时间、决策人……）；什么程度算「清楚」。
3. **逐条判定四档**：
   - 现在能做（【现有】，可进合同）
   - 换个方式能做（配置或权宜做法，不是产品能力，不进合同）
   - 规划中（【原型/规划】，只能讲方向，不进合同，不讲上线时间）
   - 做不到（进「发给产品」清单）
   - 每条附证据来源；沿用现有合同可写卫兵。
4. **三样产出**：
   - 需求判定表（售前内部看）
   - 「发给产品」清单：纯文本，一键复制；每条写客户、原话、场景、为什么现在做不到
   - 客户版 HTML 场景说明：只含「能做 / 换个方式能做」，规划项按口径写，不出现内部判定词
5. **不做**：报价定价、行业包、全量 93 篇手册同步、替代正式产品手册、现场陪访。
6. **试点指标**：沿用 §2 四项（出方案耗时、合同可写违规 = 0、每周使用次数、客户确认率），另加「发给产品的需求条数 / 周」。

## 0. 一句话判断

不是从零做平台。**「会前方案包」引擎已经可跑（PS-1～PS-23）**，缺的是三样：
1. 真人在用（部署、登录、试点售前）；
2. 知识底座能持续更新（手册 12 篇 → 全量，诚实表跟着上线公告走）；
3. 从「会前一次性出方案」扩成「售前全流程」（客户确认 → 改版 → 招标应答 → 复盘）。

路线按这个顺序走，**每阶段先能用、再扩面**。

## 3. 路线图（Now / Next / Later）

### 阶段 1 · Now：让 3～5 个售前真用起来（约 2～4 周）

目标：会前方案包从「demo」变成「每周有人用」。

| 做什么 | 验收 |
|---|---|
| 本机跑通 + 接 DeepSeek（陪跑模式，PM 代跑） | 一份五问 → 6 块包，全流程在本机走通 |
| 完成 handoff Top 3：光谱诚实分层（现有 1:1 / 规划多图）、竞赛规则口径表、积分激励一页纸 | fixtures 过；合同可写列只有【现有】 |
| PACK 导出 Word/PDF（国内客户常要文档版，飞书文档次之） | 一键得到可发客户的文件 |
| 试点记录表：每份方案记 提交时间、交付时间、批准/驳回、合同可写违规、客户是否确认 | 四项指标能直接算出来 |
| 试点 3～5 人，每周 15 分钟回访 | 2 周内收集 ≥10 份真实方案 |
| （延后）部署到国内云 + 飞书登录 | 试点证明有用后再做 |

不做：全量 93 篇同步、定价报价、行业包、截图墙。

### 阶段 2 · Next：知识底座能自己长（约 4～6 周）

目标：手册和诚实边界不靠人肉对齐。

| 做什么 | 验收 |
|---|---|
| 手册入库管线：12 篇 → 按大类分批扩（先补试点里被问最多的大类） | 每篇有来源、日期、现有/原型/规划标签 |
| 诚实表与上线公告挂钩：release-kit 每期发布后 2 个工作日内更新【现有】 | 上线公告 → 诚实表变更有记录 |
| 「待确认」问题回流：售前问到手册没有的，自动进产品侧待答清单 | 每周可看「被问但答不了」Top 10 |
| 调查/评估摘录（有正文才做，缺则标待确认） | 无编造能力 |

### 阶段 3 · Later：从会前扩到售前全流程

按试点数据排优先级，候选：

1. **方案版本**：客户确认后改版，保留 v1/v2 差异和客户原话。
2. **招标/RFP 应答**：把客户技术需求表逐条对到【现有】/【规划】/【不支持】，输出应答表（中国区招投标高频，推断）。
3. **演示支持**：截图墙、演示账号、演示脚本（handoff 标 P2）。
4. **客户档案与复盘**：赢单/丢单原因回填，反哺推荐组合。
5. **企微/飞书机器人入口**：售前在群里直接发五问。
