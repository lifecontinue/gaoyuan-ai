M0 · 基线（已上线，仅作对照）

篇幅刻意短：后续 Milestone 都建立在「末级可本地上传资料」之上。
已上线 · 2026-11-03

目标一句话：管理员在图谱第三步可为末级标签直接上传非课程资料（PPT/Word 等）并进入资料中心，支撑「仅资料 / 有资料+题 / 暂无」三类绑定中的前两类落地能力。

达到后可实现的业务场景

场景 · 管理员补齐岗位技能阅读材料

心连心 / 供应链等客户的岗位标准里，大量末级是「应知」阅读件，不一定马上有考试。管理员在配资源步骤本地上传资料，学员即可在光谱里看到并学习，不必先等课程制作或题库就绪。

痛点（上线前）：末级只能挂课程/考试链路，资料要绕资料中心另配，建图节奏被卡住。

收益：建标与挂资料可同屏完成；为 M3「非必需启用」与「多文件一次传」打底。

M1 · 批量导入与建图提效

当前周期主包 · 约至 2026-11-13 · 依赖：M0 资料上传能力已可用
当前周期

目标一句话：让客户把线下 Excel 里的岗位序列 / 分层分类标签树与学员末级能力等级 L1–L5 低成本灌进光谱；导入失败时管理员在页面内一次看清行级错误；标签名不再被长度与常用符号卡死；能力结果可进入能岗匹配度计算（含线下考试分比例口径）。

达到后预期解决的问题 / 可实现的业务场景

场景 1 · 管理员 · 供应链 / 心连心岗位序列灌标

客户 HR / 业务已在线下整理《分层分类目录》《任职资格标准》。管理员下载标签/标准树模板，按一/二/三级标填入后导入，生成光谱标签树并可选填写适用层级（L1–L5，仅控制展示）。随后建图、挂资源、关联岗位、启用下发。

痛点：手工逐条建标极慢；导入体验不友好；特殊符号或超长三级标名直接失败；错误只靠下载 xls，定位慢。

收益：批量建标可复用客户原表结构；PRO-348 放宽名称约束后，「含括号/破折号/较长技能名」的真实岗位项可入库。

场景 2 · 管理员 · 线下评委定稿后导入能力等级

评委线下完成勾叉与评议后，业务整理各学员各末级的最终 L1–L5（可选显式「待提升=是」）。管理员走「能力等级导入」：导出预填模板 → 填 L → 页内预览（行号/状态色/原因）→ 确认写入。光谱不重算评委比例，不替代外部任职资格。

痛点：旧「评分/胜任力指数」语义与客户 L 职级不对齐；误把 A–E 标准要求当学员结果导入。

收益：入口改名与双模板隔离概念；写入即最终结果，短板学习可基于「待提升」与 L 结果展开。

场景 3 · 管理员 · 导入报错一次看全（N2 / 开环）

无论是能力等级导入还是图谱/标签 Excel 导入，管理员上传后若有校验失败，不必先下错误表也能在后端页面看到全部（或本批收齐的）行级错误：哪一行、哪个字段、什么原因。错误量过大时可分页/筛选；下载明细可作为可选保留。

痛点：现网图谱导入写 errorList 后落文件再下载；分段遇错即提前 return，难以「一次看全」。

收益：客户试点（如供应链中心真实岗位数据）迭代速度明显提高；与领导演示时失败可当场解释。

场景 4 · 产品/实施 · 能岗匹配度（B-match）

光谱侧合并「线上考试/末级测评」与「线下面试分」时，需明确分值比例与录入模板/说明，避免实施口头约定不一致。可与 PRO-333 旁支同迭代给开发细则。

痛点：开环已点名，但尚无独立票与成文规则。

收益：匹配度展示与导入字段有据可依，试点汇报页口径统一。

M2 · 人·岗·图关系重构

约 2026-11 月底–12 中 · 主依赖：图谱创建流程改造就绪；与 M1 导入可并行，但「下发/回收」行为以本 M 为准
进行中

目标一句话：把「人—岗位—图谱」从易误推误收的强耦合，改成自动同步可开关、支持一岗多图谱、学员可在 PC/H5 切换自己可见的多张图谱；客户需要手工名单时能关掉自动同步。

达到后预期解决的问题 / 可实现的业务场景

场景 1 · 管理员 · 岗位人员变动不再误推 / 误收

自动同步默认开：岗图强绑定，岗位加人则自动下发图谱，减人则回收。客户若要做试点白名单或「创建时选岗仅首次灌入、之后手工维护关联学员」，可在创建/设置里关闭自动同步——关=与岗位解绑语义下，名单固定后走「关联学员」手工维护。

痛点：岗位编制一变，学员侧图谱突然消失或误发到不该学的人；实施不敢开自动同步。

收益：默认省事、可关可控；对外话术与 Feature A05「首期只岗位」一致（不主推群组）。

场景 2 · 管理员 · 同一岗位挂多张图谱

例如「运维岗」同时需要「应知通用图谱」与「高压柜专项图谱」。管理员可为同一岗位创建/关联多张图谱并分别启用；下发规则跟随自动同步开关。

痛点：一岗只能绑一图时，要么塞成巨型图谱，要么拆岗造假数据。

收益：图谱粒度可按主题拆分，学习路径更清晰。

场景 3 · 学员 · PC / H5 多图谱切换

学员被下发多张图谱时：H5 用弹窗选择，并对「与当前岗位匹配」的图谱做 highlight；PC 用 dropdown 切换。切换后学习进度、待提升项按当前图谱上下文展示（Step4 口径）。

痛点：多图并存时学员找不到入口或误以为系统丢了学习任务。

收益：人发/光谱列表体验可理解；为后续「同岗不同学员不同图」打下交互基础。

M3 · 资源弹性与启用松绑

口径 2026-10-30 已拍板 · 现网启用校验仍硬 · 可与 M1 并行，不强绑 PRO-333 DDL
Backlog · 应推进

目标一句话：末级考试/资料改为非必需；管理员在第三步一眼看到「未挂资源」的标签；支持三类绑定（仅资料 / 有资料+题 / 暂无）；并确认或补齐「多份资料一次上传」。

达到后预期解决的问题 / 可实现的业务场景

场景 1 · 管理员 · 先建标签后补资源仍可推进启用

客户建标往往先有标签树、后有课与题。拍板后：末级不再强制「必须同时有 COURSE 且 EXAM」才能启用（现网 TAG_RESOURCE_IS_NOT_ENOUGH 硬校验需改）。允许「仅资料」「暂无资源」等落位；具体「空资源能否直接启用」以 PRO-382 落地策略（强提示 / 可启用 / 分企业）为准。

痛点：客户今日仍反馈「标签必须关联课程和测试」——与 10-30 口径同族，是落地差而非新需求。

收益：建图节奏跟得上客户线下标准发布节奏；白名单跳过不再是唯一出路。

场景 2 · 管理员 · 第三步「未挂资源」明确提示

在「给末级标签配资源」步骤，对未关联课程/考试/资料的末级给出明确 UI 提示（非仅导入校验文案），让管理员扫一眼知道缺口清单，再决定补资源或按策略启用。

痛点：启用失败才报错，定位成本高。

收益：配资源步骤成为质量门，而不是事后排错。

场景 3 · 管理员 · 一次挂多份资料到资料中心（N1）

在 M0 单文件/已有上传能力基础上，若现网不支持多选，则补：一次选择多份文件并行上传并绑定到当前末级（或进入资料中心再绑）。格式上限与「同步」语义（进资料中心 vs 进度条）在验收时写死。

痛点：几十份应知 PPT 逐个点上传。

收益：与三类绑定中的「仅资料」场景配套，试点材料准备更快。

M4 · 一图多岗与标签树维护

达到后预期解决的问题 / 可实现的业务场景

场景 1 · 管理员 · 一图多岗下发

通用安全应知图谱需要同时发给「运维岗」「仓储岗」等多个岗位。管理员在图谱创建/关联时多选岗位，一次启用后按各岗位同步规则下发。这与 M2「一岗多图」方向相反、互补：M2 解决一岗拆多图；M4 解决一图复用多岗。

痛点：现在只能复制多张几乎相同的图谱分别绑岗，标准一改就要改 N 次。

收益：通用图谱一处维护；岗位覆盖面扩大时边际成本低。

代码差距已确认「确定未上线」；勿与 PRO-339 混为一谈。群组维度是否一期纳入仍战略未锁（B4/B5）。

场景 2 · 管理员 · 自建标签批量移动 / 分类可删

标签树在多轮导入与手工调整后会出现错位分类。管理员可多选自建标签批量移动到目标分类，并可删除空的或废弃的标签分类，而不必逐条拖拽。

痛点：树一深，整理成本高于建标本身。

收益：小工具高杠杆，尤其服务频繁改标的试点客户。

场景 1 · 管理员 / 教研 · 题目难度与试题管理统一

客户要求给题目打难度标签，并最好直接用现有「试题管理」的难度字段，而不是在光谱图谱里再维护一套题。拍板后的目标态：光谱挂题时读取/同步平台难度；抽题或展示可按难度筛选；存量图谱题迁移策略单独定。

痛点：光谱 ElsQuestion 无难度字段；图谱题与平台题库分轨，重复维护。

收益：一套题库多处复用；难度语义与职级验证可组合。

场景 2 · 学员 · 按职级看到不同验证难度（A03）

同一末级能力项，初级工与技师验证强度不同。系统按学员职级（或 L）关联不同难度试卷/题集，而不是只靠「适用层级控制展示」近似替代。

痛点：开环「验证规则 L1–L5 已支持」≠ 难度标签 + 试题管理打通；对外需避免话术混用。

收益：验证梯度可解释，贴近任职资格分层。

场景 3 · 远期 · 验证不止考试（A9）

360、问卷、易培等非考试验证形态与光谱短板闭环的耦合面大，本 Milestone 只登记为远期，不承诺本期交付。
