# 可扩展架构方案（[孩子]成长星空）

> 版本：v1.0 · 2026-08-04
> 目标：**明确模块边界、接口规范与分层结构**，使后续能**低成本接入与扩展更多 AI 功能**，同时保持离线单页、可双击运行的形态。
> 配套文档：`docs/工具前端设计说明.md`（功能/流程/选型/视觉）、`docs/系统设计Prompt.md`（持续优化指导）。术语与结构保持一致。

---

## 1. 设计目标与原则

| 目标 | 说明 |
|---|---|
| 清晰边界 | 每个模块单一职责，依赖方向自上而下，禁止反向/跨层乱调 |
| 接口先行 | 模块间只通过「契约」通信，实现可替换（尤其 AI） |
| AI 可插拔 | AI 能力抽象为 Provider 接口；本地规则与云端 LLM 并存、可配置、可降级 |
| 离线兜底 | 任何联网/AI 能力都有本地降级，基础功能永不因 AI 失败而中断 |
| 渐进演进 | 不推倒重写；从现有单文件平滑迁移到模块化 |

**依赖方向（只允许向下依赖）**：表现层 → 应用层 → 领域层 → 数据层；集成层（AI/外部）只被应用层调用，不反向依赖 UI。

```
│   成长模型：domains/periods/indicators/subjects                   │
```

**当前代码 → 分层映射**（不必立刻移动文件，先认清归属）：

| 分层 | 当前代码归属 |
|---|---|
| L1 表现 | `index.html`、`css/style.css`、`js/galaxy.js`、`js/charts.js` |

## 3. 模块边界与职责

| 模块 | 层 | 职责 | 拥有 | 不得做 |
|---|---|---|---|---|
| GalaxyEngine | L1 | 3D 建模/渲染/镜头/悬停 | 节点构建、投影、信息卡 | 不写业务文案、不直连 store |
| Charts | L1 | 雷达/折线/堆叠 SVG | 纯绘制 | 不取业务数据（数据由应用层传入） |
| SidePanel | L1/L2 | 详情容器显隐与刷新 | `render/show/hide/refresh` | 不管内容生成 |
| AppRouter | L2 | 按节点/菜单路由到具体 render | `openNode/openMenu` | 不含业务计算 |
| DetailViews | L2 | 生成各详情/面板 HTML | `renderCenter…renderData` | 不写库（写库走 Store） |
| SearchService | L2 | 索引构建与命中定位 | `buildSearchIndex/doSearch` | 不管镜头（交 Galaxy.focusNode） |
| AIOrchestrator | L2 | 组装上下文、调用 Provider、管理会话 | 见 §5 | 不直接实现 LLM 逻辑 |
| GrowthDomain | L3 | 评分/阶段/趋势/汇总 纯函数 | 领域计算 | 不碰 DOM/存储 |
| Store | L4 | LocalStorage CRUD + 版本迁移 | notes/habits/parentPeriods/summaries/overrides | 不含业务规则 |
| SeedData | L4 | 只读种子 | data.js / subjects_p3.js | 永不被修改 |
| AIProvider | L5 | AI 能力实现（可替换） | chat/analyze/suggest | 不依赖 UI |

## 4. 接口规范（契约）

> 以下为**建议契约**（JSDoc 形式）。现有 `window.TT/Galaxy/Store` 保持兼容，新契约以「扩展」方式落地。

### 4.1 节点对象（GalaxyEngine ⇄ AppRouter）
```js
/**
 * @typedef {Object} GalaxyNode
 * @property {string} id
 * @property {'center'|'domain'|'subdomain'|'indicator'|'subject'|'theme'|'pindicator'} kind
 * @property {string} label
 * @property {string} [en]
 * @property {string} color
 * @property {number} size
 * @property {number[]} pos3            // [x,y,z] 球面坐标
 * @property {Object} data              // 业务负载（领域key/学科index/指标row等）
 */
// 回调契约：节点点击
// Galaxy.clickNode(node) -> TT.openNode(node)
```

### 4.2 详情渲染契约（DetailViews → SidePanel）
```js
/**
 * SidePanel.render(crumbs, html, cur)
 * @param {string} crumbs        面包屑 HTML（当前层级用 <b>）
 * @param {string} html          正文 HTML（已 esc）
 * @param {{fn:Function, args:any[]}=} cur  刷新句柄：数据变更后 Side.refresh() 重放
 */
// 约定：cur 必须可重入（幂等），不依赖已失效的 DOM 引用。
```

### 4.3 AI 消息契约（应用层内部 + Provider）
```js
/**
 * @typedef {Object} AIMessage
 * @property {'user'|'ai'|'system'} role
 * @property {string} html       // 展示用（可含受控标签）
 * @property {string} time
 */
/**
 * @typedef {Object} AIContext
 * @property {'galaxy'} route
 * @property {string|null} domain
 * @property {string|null} metric
 * @property {string|null} menu
 * @property {'k'|'p'} stage
 */
```

### 4.4 AI Provider 契约（**AI 可插拔的核心**）
```js
/**
 * @interface IAIProvider
 * 所有 AI 能力（本地规则 / 云端 LLM / 未来更多）都实现此接口。
 */
class IAIProvider {
  get name() { return 'abstract'; }        // 标识
  get ready() { return true; }             // 是否可用（用于降级判断）

  /** 快捷动作/意图分析：趋势/薄弱/计划/报告/活动 等
   * @param {{intent:string, context:AIContext, payload?:any}} req
   * @returns {Promise<{html:string, chips?:Array<{id,icon,label}>}>}
   */
  async analyze(req) { throw new Error('not impl'); }

  /** 自由问答
   * @param {{text:string, context:AIContext, history:AIMessage[]}} req
   * @returns {Promise<{html:string}>}
   */
  async chat(req) { throw new Error('not impl'); }
}
```
- **RuleProvider（现实现，默认兜底）**：本地统计规则，`ready` 恒为 true，云端 Agent 不可用时自动回落。
- **DeepSeekProvider（已实现，双 Agent）**：`deepseek-k-provider.js`（幼儿园·幼儿发展评估专家，《3~6岁指南》六大领域）与 `deepseek-p-provider.js`（小学·学科评估专家，2022 课标九大学科核心素养）；二者经 `deepseek-core.js` 共享内核 `createDeepSeekProvider` 自注册到 `ProviderRegistry`。`ready` 恒为 true（代理可达即视为就绪），`call` 走服务端代理 `/api/ai/chat`（Key 不在前端）。`ProviderRegistry.pick(stage)` 按阶段择优：优先 `stage` 匹配者，否则回落 `RuleProvider`。

### 4.5 存储契约（Store + 版本迁移）
```js
/**
 * StorageSchema v1（LocalStorage key: tuantuan_growth_v1）
 * {
 *   version: 1,

 *   overrides: { 'periodId::indKey': {l?, r?} },

```

## 5. AI 能力接入架构（重点）

### 5.1 组件与数据流
```
用户输入/快捷动作
   │
   ▼
AIOrchestrator（L2）
   │ 1) ContextBuilder.build()  → 组装 AIContext + 领域统计快照（当前期/强弱域/待突破）
   │ 2) PromptRegistry.get(intent) → 取该意图的提示词/模板（LLM 时生效，本地规则可忽略）
   │ 3) ProviderRouter.pick() → 选可用 Provider（LLM 不可用时回落 Rule）
   ▼
IAIProvider.analyze / chat（L5）
   │
   ▼
AIOrchestrator 渲染：post(role, html) + renderQuick(chips)
```

### 5.2 关键件职责
| 件 | 职责 | 输入 → 输出 |
|---|---|---|
| ContextBuilder | 把 UI 上下文 + 领域数据浓缩成 AI 可用快照 | `{route,domain,metric,menu,stage}` + Domain 计算 → `AIContext+snapshot` |
| PromptRegistry | 管理各意图的 prompt 模板（趋势/薄弱/计划/报告/活动） | `intent` → prompt 模板字符串 |
| ProviderRouter | 按配置与健康度选 Provider，处理降级 | 已注册 Provider 列表 → 可用实例 |
| ProviderRegistry | 注册/枚举 Provider | `register(provider)` / `list()` |

### 5.3 新增一个 AI 能力的标准步骤（示例）
1. 实现 `IAIProvider`（如 `GrowthInsightProvider`），给出 `name/ready/analyze/chat`。
2. `AIProviders.register(new GrowthInsightProvider(config))`。
3. 如需新意图：在 `PromptRegistry` 登记 `intent → 模板`，并在快捷动作表加 `{id,icon,label}`。
4. 编排器不变；Provider 不可用时自动降级，不报错。

```js
// 伪代码：注册与降级
const providers = AIProviders.list().filter(p => p.ready);
const provider = ProviderRouter.pick(providers) || new RuleProvider();
const { html, chips } = await provider.analyze({ intent, context, payload });
AI.post('ai', html); if (chips) AI.renderQuick(chips);
```

### 5.4 可扩展的 AI 能力清单（未来接入点）
| 能力 | 意图 id | 数据来源 | 说明 |
|---|---|---|---|
| 成长趋势解读 | trend | 领域趋势/跨期 | 已有规则版 |
| 薄弱项定位 | weak | registry/待突破 | 已有规则版 |
| 改进计划生成 | plan | 薄弱域+学科维度 | 已有规则版，可升级为 LLM |
| 综合报告撰写 | report | summaryData | 已有规则版，可升级为 LLM |
| 亲子活动推荐 | activity | 学科/领域 | 已有规则版 |
| **观察记录润色**（新）| polish | notes 文本 | 典型 LLM 场景，离线降级=原样返回 |
| **跨周期自然语言问答**（新）| qa | 全量数据快照 | 需 LLM + ContextBuilder |
| **异常波动预警**（新）| alert | 跨期差分 | 规则即可实现 |

> 原则：**新 AI 能力 = 新增 Provider（+ 必要时新增 intent/模板），不改动编排器与 UI。**

### 5.5 现状同步（2026-08-04 · 已实现）

架构已从「规划」落地为可运行的双 Agent + 服务端 Key 方案：

**模块映射（实际文件）**
| 规划件 | 实际实现 | 说明 |
|---|---|---|
| AIOrchestrator（L2） | `js/ai/orchestrator.js` | `welcome/action/reply` → `runWithFallback(stage, method, args)`；云端失败回落 `RuleProvider` |
| ContextBuilder | `js/ai/context-builder.js` | 组装 `AIContext + 领域统计快照`，含 `stage/stageLabel` |
| ProviderRegistry | `js/ai/provider-registry.js` | `register/list/pick(stage)`；`pick` 优先阶段匹配、回落 `rule` |
| 双 LLM Provider（已实现）| ~~旧 `js/ai/providers/deepseek-{core,k,p}-provider.js`~~ → **新架构** `js/ai/kindergarten/` + `js/ai/primary/` | 每个 specialist 独立 `provider.js` + `prompt.js` + `knowledge.js`，prompt 与代码分离 |
| 本地规则 | `js/ai/providers/rule-provider.js` | 永远 ready，作为兜底 |
| 统一入口 | `js/ai/router/education-router.js` | `educationAgent(stage, intent)` 单一入口，内部按 stage 路由 |
| 共享层 | `js/ai/shared/` | `output-schema.js`（JSON block schema）、`formatter.js`（blocks→HTML）、`memory.js`（Child Profile Memory） |

**服务端 Key（前端免输入）**
- 前端 `js/core/config.js`：`export const AI_API_BASE = ''`（默认同源）。
- `server/index.js`（Node 内置模块，无第三方依赖）：托管 `dist-generic/` 静态前端，并提供 `POST /api/ai/chat` 转发 `https://api.deepseek.com/chat/completions`；Key 取自环境变量 `DEEPSEEK_API_KEY` 或 `server/.env`（已被 `.gitignore` 忽略）。无 key 时返回友好 500，前端自动回落本地规则。
- 运行：`启动AI服务.bat`（双击）或 `node server/index.js`（默认端口 8080）。仅运行服务端 + 前端才有 AI 能力；纯静态打开 `index.html`（或旧 `dist-single/`）时 AI 自动降级为本地分析，其余功能正常。
- **子路径部署**：通过环境变量 `BASE_PATH`（如 `/tuantuan`）即可把整个应用挂在 `https://host/tuantuan/` 下；前端会按页面路径自动推断基址，`/api/ai/chat`、`/mediapipe/` 均随之生效，无需改动代码。摄像头仍需安全上下文（localhost 或 https）。
- **手势控制自托管资源**：`server/index.js` 另托管 `/mediapipe/` 静态路由（含 `application/wasm` MIME），提供 MediaPipe Hands 0.4 的 `hands.js` / `hands_solution_simd_wasm_bin.wasm` / `.data` / `.binarypb` 等（位于 `server/public/mediapipe/`，约 11MB，未被 `.gitignore` 忽略）。前端 `js/gesture/gesture-controller.js` 优先从 `/mediapipe/` 加载（离线/云端一致），失败才回落 CDN。**离线（本地起服务）与云端（部署同一 Node 服务）的手势能力完全相同**。`server/download-mediapipe.bat` 可重新拉取这些资源。

**前端面板交互**
- `index.html` 右上角常驻 `#aiLaunch` 按钮；AI 面板内 `#aiMin` 收起按钮。两者均用 `classList.toggle('collapsed')`，确保收起后可再次调出（已修复「关闭后无法再打开」）。
- 阶段切换（`#galStage`/`#stageMini`）触发 `window.AIPanel.onStageChange()` → 以当前阶段 Agent 重新生成欢迎语。
- Key 输入框已从前端完全移除。

**AI 流式回复 + 富交互**
- 流式：`server/index.js` 的 `handleChat` 支持 `stream`（默认开），把 DeepSeek 的 SSE 透传（`text/event-stream`，关闭代理缓冲）；Specialist Provider 的 `stream()` 逐块解析 `data:` 行；`educationAgent` 统一入口缓冲 JSON → 解析 → 渲染 HTML；失败回落 `RuleProvider`。
- **新架构 JSON Schema**：Agent 返回 `{stage, blocks:[...]}`，每个 block 6 种类型（paragraph/heading/list/activity/indicator/action）；`shared/formatter.js` 声明式渲染为 HTML（活动 chip / 指标 chip / 按钮）；前端只需调用 `educationAgent.welcomeStream(stage, onHtml)`。
- Rich content：不再使用正则标记 `[[活动:]]` / `[[指标:]]`，改为 Agent 直接输出 JSON activity/indicator blocks（前端自动渲染）。
- **Child Profile Memory**：`shared/memory.js` 的 `buildChildProfile()` 每次调用前从 Store 读取孩子信息并注入 system prompt。

## 6. 模块间通信

- **现状**：`window.TT/Galaxy/Store/Charts` 全局单例直接互调（够用，但耦合）。
- **演进**：引入轻量 `EventBus`（发布/订阅），用于「跨层、跨模块」的解耦通知；UI 内部直调仍保留。
```js
// 事件命名约定 domain/action：'stage/changed'、'node/opened'、'data/imported'、'ai/context'
EventBus.on('data/imported', () => { SearchService.rebuild(); SidePanel.refresh(); });
EventBus.emit('stage/changed', { stage });
```
- **规则**：数据变更统一 `emit`；关心方 `on`；避免在 UI 层互相持有引用。

## 7. 目录重构建议（单文件 → ES Modules，仍可双击运行）

> 分两步：先「物理分文件、逻辑不变」，再「依赖反转、接口落地」。全程保持无构建。

```
├─ index.html                 # 改为 <script type="module" src="js/main.js">
├─ css/style.css
├─ js/
│  ├─ main.js                 # 入口：装配各模块（替代现 init 的编排）
│  ├─ core/
│  │  ├─ event-bus.js         # EventBus
│  │  ├─ utils.js             # esc/toast/modal/download/esc 等
│  │  └─ config.js            # 常量、评分口径、菜单、阶段
│  ├─ domain/
│  │  ├─ growth.js            # keyRows/registry/stagePeriods/avgOf/趋势/强弱（纯函数）
│  │  └─ subjects.js          # 学科维度纯逻辑
│  ├─ data/
│  │  ├─ store.js             # LocalStorage + version/migrate
│  │  ├─ data.js  └─ subjects_p3.js   # 只读种子（保持现状）
│  ├─ ui/
│  │  ├─ side-panel.js        # Side 对象
│  │  ├─ detail-views.js      # renderCenter…renderData（DetailViews）
│  │  ├─ search.js            # SearchService
│  │  └─ widgets.js           # modal/toast/通用模板
│  ├─ viz/
│  │  ├─ galaxy.js            # GalaxyEngine
│  │  └─ charts.js            # Charts
│  └─ ai/
│     ├─ orchestrator.js      # AIOrchestrator
│     ├─ context-builder.js
│     ├─ prompt-registry.js
│     ├─ provider-registry.js
│     └─ providers/
│        ├─ rule-provider.js  # 本地规则（现 AI 逻辑迁入）

```

**迁移注意**：
- `<script type="module">` 下 `file://` 受 CORS 限制，**双击运行需本地起一个静态服务**（或改用单文件内联模块）。若必须「双击即用」，则先做「逻辑分层但物理仍少文件」的折中（用立即执行函数分区），待引入构建后再拆 ES Modules。**这一点在 选型建议 §4.3 已提示，二选一。**

## 8. 迁移路线（阶段化 Roadmap）

| 阶段 | 目标 | 动作 | 验收 |
|---|---|---|---|
| P0（当前） | 稳定现状 | 已完成星空核心重构 + 无头回归 54/54 | 回归全绿 |
| P1（近期） | **AI Provider 抽象落地** | 抽 `AI` 规则 → `RuleProvider`；建 Orchestrator/ContextBuilder/Registry；UI 改走 Orchestrator | 行为与现状一致；新增 Provider 不改 UI 即可生效 |
| P2 | 逻辑分层 | 抽 L3 领域纯函数出 `app.js`；引入 EventBus | 领域函数可独立单测 |
| P3 | 数据健壮性 | Store 加 `version` + `migrate`；导入导出带版本 | 旧数据无损升级 |
| P4 | 接入真实 AI | 实现 `LLMProvider`（可配置开关，默认关）+ PromptRegistry | 无配置时自动降级 Rule；有配置走云端 |
| P5（按需）| 工程化 | Vite + TS + PWA + Playwright 视觉回归 | 打包产物仍可离线运行 |

> 里程碑建议：**P1 与 P2 是当前性价比最高的两步**，先把 AI 接口立起来、把领域计算抽纯，后续所有 AI 扩展都顺。

## 9. 不变量（任何演进都不得破坏）

1. 离线可运行；无强制外部依赖。
2. 星空为唯一主界面；功能浮层化。
3. `window.TT/Galaxy/Store/Charts` 既有公开方法签名向后兼容。
4. 评分口径与状态色统一。
5. 写库操作必有确认 + 反馈；数据导入带版本迁移。
6. AI 失败/无网络时，基础功能不受影响（降级而非报错）。
