# 需求 → 上线 工作流（真源）

> 2026-09-29 用户口述（实证）。Linear 拆子任务、写日报、判断需求卡在哪一步，都按本文。

## 全流程

| # | 环节 | 谁 | 产品动作 | 出口 |
|---|---|---|---|---|
| 1 | 提交需求 | 一线 | — | 飞书需求池新记录 |
| 2 | 需求评审 | **产品** | 每周二 14:00 评审；裁决纳入 / 不纳入 / 后续 | 池内评估结论 |
| 3 | 方案细化 | **产品** | 对纳入优化的需求补需求文档 + 原型，提交 Jira | Jira 单（挂飞书文档链） |
| 4 | 定排期与跟进 | **产品** + 开发 | 和开发定排期；日常跟进进度 | Jira 预计上线日；提测 |
| 5 | 测试验收 | 测试 | —（开发完成后邮件给测试） | 测试通过，转给产品 |
| 6a | 测试环境验收 | **产品** | 在测试环境验收 | 通过 / 打回 |
| 6b | 部署 | **产品** → CI/CD | 验收通过后发给 CI/CD 部署 | 部署完成 |
| 6c | 正式环境验收 | **产品** | 部署后在正式环境再验收 | 通过 / 回滚或补修 |
| 6d | 闭环 | **产品** | 回飞书文档 / 需求池更新上线状态 | 池状态 = 已上线 |

## 产品名下的标准子任务（Linear）

父 Issue = 一条需求。子任务只建**产品本人要做**的环节，已完成的环节不重复建（已有日报实证子项视为覆盖）。标题格式：`【环节】动作 · 需求简称`。

| 标签 | 标题 | 完成判据 |
|---|---|---|
| 【评审】 | 周二 14:00 需求评审 | 池内裁决已填；纳入才继续往下建 |
| 【方案】 | 补需求文档 + 原型，提交 Jira | 飞书文档链已挂 Jira |
| 【排期】 | 与开发确定排期 | Jira 预计上线日已确认 |
| 【跟进】 | 跟进开发进度至提测 | 开发已邮件提测给测试 |
| 【验收·测试环境】 | 测试通过后验收测试环境 | 产品验收通过（前置：测试通过邮件） |
| 【部署】 | 提交 CI/CD 部署 | CI/CD 部署完成 |
| 【验收·正式环境】 | 验收正式环境 | 正式环境走查通过 |
| 【闭环】 | 回飞书更新上线状态 | 需求池 / 飞书文档状态已更新，一线已知会 |

规则：

- Triage / 未评审的需求只建【评审】，裁决纳入后再补后面的子任务（对齐 intake 漏斗「accept 才写 PRD」）。
- 测试环节（5）不归产品，不建子任务；它是【验收·测试环境】的前置。
- 多端分批上线（如服务端 / APP）时，【部署】【验收·正式环境】可按端拆。
